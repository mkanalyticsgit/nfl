## Project Purpose

A **free, web-based NFL player analytics and fantasy football tool**.
Users can search players, view historical stats, analyse matchups, and get
AI-generated insights via natural language. No subscription required.

---

## Tech Stack

| Layer      | Technology                                   |
|------------|----------------------------------------------|
| Data       | `nfl_data_py` (Python nflverse wrapper)      |
| Backend    | Python 3.13 + FastAPI + Uvicorn              |
| Database   | DuckDB (file-based, `backend/data/nfl.duckdb`) |
| Frontend   | React + Vite + Tailwind CSS + Recharts       |
| Hosting    | Render.com (backend) + Vercel (frontend)     |

## Database Schema (DuckDB — `nfl.duckdb`)

Tables are created by `backend/data/fetch.py` using `nfl_data_py`:

| Table           | Key Columns                                                                 |
|-----------------|-----------------------------------------------------------------------------|
| `rosters`       | `player_id`, `player_name`, `position`, `recent_team`, `season`            |
| `seasonal_stats`| `player_id`, `season`, `fantasy_points_ppr`, passing/rushing/receiving cols |
| `weekly_stats`  | `player_id`, `season`, `week`, `recent_team`, `opponent_team`, stat cols   |
| `schedules`     | `season`, `week`, `home_team`, `away_team`, `game_id`, `gameday`           |

All column names are lowercased. Seasons currently loaded: **2019–2024** (stats),
**2019–2025** (rosters & schedules). 2025 player stats will be available once
nflverse publishes them after the season begins.

**Important:** The `rosters` table (from `import_seasonal_rosters`) uses `team`
not `recent_team`. The `weekly_stats` table uses `recent_team`.

All query helpers use `_to_records(df)` which calls `df.to_json()` then
`json.loads()` to safely convert NaN → null before returning to FastAPI.

## API Endpoints

### Players
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/players/search?q=&limit=` | Name search |
| GET | `/api/players/{player_id}` | Roster/bio info |
| GET | `/api/players/{player_id}/stats/seasonal?seasons=` | Per-season stats |
| GET | `/api/players/{player_id}/stats/weekly?season=&last=` | Weekly game log |

### Matchups
| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/matchups/upcoming/{team}?season=&week=&n=` | Next N games |
| GET | `/api/matchups/defense/{team}?position=&season=` | Pts allowed by position |
| GET | `/api/matchups/player/{player_id}/matchup?season=&week=` | Full matchup check |

## Running Locally

### Backend
```bash
cd backend
# Install deps (note: nfl_data_py needs --no-deps due to stale pandas<2.0 pin)
pip install nfl_data_py --no-deps
pip install fastapi "uvicorn[standard]" duckdb pandas python-dotenv appdirs fastparquet

# First time — populate the database (takes 2-5 minutes)
python data/fetch.py

# Start the API
python -m uvicorn main:app --reload --port 8000
```
API at `http://localhost:8000`. Interactive docs at `/docs`.

### Frontend
```
# The & in the OneDrive path breaks npm's cmd launcher on Windows.
# Work around by mapping the folder to a drive letter first:
subst V: "<full path to Player Stats Tool folder>"
cd V:\frontend
npm run dev
```
App at `http://localhost:5173`. Vite proxies `/api` → `http://localhost:8000`.

## Coding Conventions

- All route functions return plain dicts (FastAPI serialises to JSON).
- `cache.py` owns all SQL — routes never write raw DuckDB queries.
- DuckDB connections are opened per-request (read-only) and closed immediately.
- Pydantic models are defined in the same route file that uses them.
- Frontend API calls all live in `src/api.js` — pages never call `fetch()` directly.
- Avoid adding dependencies not already in `requirements.txt` / `package.json`.
